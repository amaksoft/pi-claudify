# Appearance settings are user-scoped: the project file is ignored

Supersedes [ADR 0003](0003-project-overrides-user-settings.md). Everything this extension configures is personal presentation — spinner color, message chrome, diff palette, tool-row grammar — the same category as a terminal theme or editor font, and a user's TUI should not restyle itself between repositories. Worse, `.pi/settings.json` can be committed, which would let a repo author restyle every contributor's TUI. Claude Code keeps appearance in user config for the same reason. So in 2.0.0 the extension reads only `~/.pi/settings.json` and ignores the project `.pi/settings.json` entirely for its own keys (pi itself still uses project files for pi's own settings). This dissolves the shadowed-write problem ADR 0003 had to manage — a write can no longer be silently overridden by a file the screen never edits — and removes the "(project)" badge and the per-key provenance map from the Claudify screen design. The unified reader from CLFY-2 keeps its single-reader design, legacy-alias normalization, cache, and per-file read status; only the project merge and `sources` provenance go. Accepted loss: deliberate per-project styling as a visual cue (a red spinner in the prod repo) is no longer possible.
